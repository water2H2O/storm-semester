### 1.1 为什么选 EdTech，不选 Data-driven

两个主题都说得通。EdTech 的描述是「帮学生改善学习的学习应用、游戏化教育」，我们的目标用户、使用场景和评判方式都在这里面。Data-driven 要求「收集、分析或可视化数据来帮人做决定」，我们也符合，但那个赛道更容易遇到真正做数据分析的队伍。

**决定：EdTech。** README 第一行、Devpost 主题选项、视频开头都写明。

### 1.2 评分标准与对应的得分点

| 维度 | 权重 | 我们拿什么得分 |
|---|---|---|
| 技术实现 | 30% | 压力引擎（类型曲线、主次排序）、天气驱动的 3D 城市、自检脚本、清楚的模块划分 |
| 演示与文档 | 30% | 打开就是城市；勾掉事项后城市放晴；README 写清架构和算法 |
| 创新 | 20% | 用天气表达压力；「提交型 / 发生型」两类事项；越远越模糊的预报 |
| 影响 | 20% | 真实日程做 demo 数据；找 3–5 个同学试用，引用他们的原话 |

技术实现从上届的 20% 涨到 30%，所以不能只靠画面好看，引擎和代码结构要讲得出来。

## 3. 产品结构：城市 + 面板

v0.1 是一个天气 app 式的单页。v0.2 改成两层：

### 3.1 城市态（默认）

打开页面先看到一座悬浮的 3D 城市，城市上空就是今天的天气。底部只留一行信息：

```
⛈ 雷暴
今天有 5 个事项到期
下一场风暴：雷暴 · 周五 11/20 · 还有 7 天
[ 查看学期详情 ↑ ]
```

- 用户不操作时，镜头缓慢环绕，展示城市全貌。
- 可以拖动旋转城市，松手后回到自动环绕。
- 往下滚、上滑或点按钮，进入面板。

### 3.2 面板态

面板从底部升起，内容从上到下：

1. **今日**：天气等级、压力值、到期数量
2. **下一场风暴**：未来 30 天第一个雷暴及以上的日子
3. **现在做这一件**：只给一件，附「已经晚了几天」和准备清单
4. **本周**：周一到周日 7 格天气
5. **未来 14 天**：横向时间轴，越远越模糊

点「回到城市」、按 Esc，或在面板顶部往上滚，退回城市。

### 3.3 完成后的反馈（演示核心）

勾掉一件事后，**自动退回城市态约 2 秒**，让用户看到城市的天气变化，然后回到面板。这个反馈要做，因为面板盖住了大半个城市，在面板里勾完看不到放晴。

## 4. 城市切换

### 4.1 要做的事

- 页面右上角加一个城市选择：**通用岛 / 香港**（之后可加伦敦）。
- 选择保存在 localStorage，下次打开保留。
- 切换时淡出旧城市，淡入新城市，天气保持不变。
- **演示默认香港。** 评委是香港人，香港城市配上天文台的风球信号，本地感最强。

### 4.2 城市模块接口（给香港模型用）

场景本身（渲染器、灯光、雾、雨、云、闪电、镜头）由 `scene3d.js` 负责。每座城市是一个单独的文件，只负责建模：

```js
// cities/hongkong.js
STORM_CITIES.register({
  id: "hongkong",
  label: "香港",
  build(api) {
    // api: THREE, group, box, cyl, cone, beam, mat, voxel, addAnim, rand
    // 在 api.group 里建地形和建筑
    return {
      windowMaterials: [/* 窗户材质，天气越差越亮 */],
      signalAnchor: [x, y, z],      // 风球信号杆的位置，可选
      camera: { target: [0, 2, 0], distance: 90 },  // 可选
    };
  },
});
```

**模型约束：**

| 项 | 要求 |
|---|---|
| 尺寸 | 水平半径约 35 单位以内，地面在 y≈0，最高约 25 |
| 依赖 | 只用全局 `THREE`，不发网络请求，不加载外部贴图 |
| 性能 | 地形和小物件用 `voxel()` 合批（一次 draw call）；目标核显 30 fps |
| 窗户 | 窗户用单独的材质，交给场景控制亮度 |
| 动画 | 用 `addAnim(fn)` 注册，不要自己开 `requestAnimationFrame` |

当前的通用岛先按这个接口拆出来（`cities/generic.js`），香港模型做好后直接放进 `cities/`。

### 4.3 天气对城市的影响

已经有的：

| 天气越差 | 表现 |
|---|---|
| 光照 | 太阳变弱变冷，整体变暗 |
| 雾 | 越来越近、越来越暗 |
| 雨 | 雨丝越来越密、越来越快 |
| 闪电 | 雷暴以上出现，越差越频繁 |

要加的（按性价比排序）：

1. **窗户亮灯**：压力越大，越多窗户亮起，像所有人都在熬夜。成本低，夜景很好看。
2. **风球信号杆**：三号、八号、黑雨时，城市里的信号杆挂出对应信号。只在香港城市做。
3. **云层下压**：天气越差，云越低越厚，晴天云散开。
4. **放晴的光**：从雷暴降到多云以下时，给一道阳光，配合 §3.3 的反馈。

不做：积水反射、行人车辆增减、树木随风摆动。效果好，但 39 小时内做不完。

## 5. 数据模型

### 5.1 事项

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识 |
| `course` | 课程代号，用于配色 |
| `title` | 名称 |
| `due` | 截止或发生时间 |
| `type` | `lab` / `per` / `interview` / `quiz` / `exam` / `custom` |
| `kind` | `submit` 提交型 / `happen` 发生型，默认来自类型 |
| `weight` | 压力权重，默认来自类型，可改 |
| `leadDays` | 准备窗口天数，默认来自类型，可改 |
| `checklist` | 准备清单，发生型才有 |

### 5.2 提交型与发生型

| | 提交型 | 发生型 |
|---|---|---|
| 例子 | lab、报告、汇报 | 考试、课上抽查、小测 |
| 完成方式 | 用户勾掉，天气立刻变好 | 不能勾掉，只能勾准备清单 |
| 结束 | 勾掉时 | 时间过了自动结束 |
| 界面 | 「标记完成」按钮 | 准备清单和进度条 |

### 5.3 类型预设

> "per" 按 presentation（汇报）处理。

| 类型 | kind | 权重 | 准备窗口 | 曲线 |
|---|---|---|---|---|
| `lab` | submit | 2 | 7 天 | 平稳 |
| `per` | submit | 3 | 5 天 | 台阶 |
| `interview` | happen | 3 | 3 天 | 陡升 |
| `quiz` | happen | 3 | 5 天 | 陡升 |
| `exam` | happen | 4 | 10 天 | 长坡 |
| `custom` | 用户选 | 2 | 用户填 | 平稳 |

曲线决定离截止还有几天时压力开始上来：

```
平稳  ▁▂▃▄▅▆▇   lab
陡升  ▁▁▁▁▂▅█   interview / quiz
台阶  ▁▁▃▃▅▅█   per
长坡  ▁▂▃▄▅▆▇█  exam
```

**当前代码的差距：** 现在所有事项都用同一条直线，`type` 字段基本都写成 `lab`。要补上类型预设和四种曲线。

## 6. 压力与天气

### 6.1 单日压力

```
P(某天) = Σ 每个未完成事项的 weight × 系数
```

| 离截止 | 系数 |
|---|---|
| 当天 | 1.3 |
| 准备窗口内 | 按曲线从 0 升到 0.85 |
| 窗口外或已过 | 0 |

### 6.2 天气等级

| 压力 | 天气 | 信号 |
|---|---|---|
| 0 | 晴 | — |
| 0.01–2 | 多云 | — |
| 2–4 | 阴 | — |
| 4–7 | 小雨 | — |
| 7–10 | 雷暴 | — |
| 10–13 | 三号风球 | T3 |
| 13–18 | 八号风球 | T8 |
| ≥18 | 黑色暴雨 | BLACK |

真实数据下 11/13 的压力是 21.2（黑色暴雨），勾掉当天 5 件后降到 1.7（多云）。

### 6.3 主次排序

每件事用「截止日减准备窗口」算出「本该开始的日子」。

1. 已经过了开始日的，排在前面
2. 同组内，离截止近的在前
3. 同一天到期的，权重大的在前

所以「期中考晚了 8 天」会排在「小组项目晚了 3 天」前面，虽然小组项目权重更高。

### 6.4 远期模糊

| 距今天 | 显示 |
|---|---|
| 0–14 天 | 正常 |
| 15–30 天 | 图标变淡，名称加「?」 |

**当前代码的差距：** 时间轴只画 14 天，模糊判断写成了 `i > 14`，永远不会触发。改成画 21 天，第 15 天起模糊。
